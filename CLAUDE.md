# CLAUDE.md

Gumption (working name): a platform where businesses at any stage run their company with an AI cofounder ("Sol, powered by Claude"). Two entry paths share one data model: **Start up** (idea or pre-launch founders, including student cohorts; gates prove demand before building) and **Keep going** (businesses already trading; enter at Grow, gates approve voice, response policy and budgets). Sol builds sites and simple apps, runs campaigns, captures and nurtures leads, listens to customers, replies in the company's own voice, captures actions from conversations and automates routine operations. Founders approve anything that matters; university and incubator mentors oversee cohorts.

Full product spec: `docs/SPEC.md`. Delivery plan: `docs/PHASES.md`. Current state: `docs/STATUS.md` (you maintain this).

## Architecture

```
React app (Lovable-generated)  ──>  Supabase (Postgres + RLS + Realtime + Edge Functions)
                                          ▲
                                          │ service role
                              agent-service/ (Node, Claude Agent SDK)
                                          │
                       Anthropic API · Stripe · Resend · Ayrshare · PostHog
```

- **Frontend:** React + TypeScript + Vite + Tailwind + shadcn/ui, generated by Lovable. Keep it Lovable-compatible: don't move `src/` structure, the Supabase client in `src/integrations/supabase/`, or rename existing components unless needed.
- **Database:** Supabase Postgres. RLS on every table. All schema changes as SQL migrations in `supabase/migrations/`, then regenerate types.
- **Edge Functions** (`supabase/functions/`): Stripe webhooks, enqueueing agent jobs, chat endpoint. Short-lived work only.
- **Agent service** (`agent-service/`): long-running Node worker using `@anthropic-ai/claude-agent-sdk`. Picks up jobs from `agent_jobs`, runs one company agent per job, writes `agent_runs`, `activity_events`, `approvals` and `credit_ledger` with the service role. Based on the prototype in `docs/prototype/` (company memory → skill → MCP tool → approval gate → audit hook → cost report).

## Non-negotiable rules
1. **Secrets.** `ANTHROPIC_API_KEY`, Stripe secret, Supabase service role key and other provider keys live only in the agent service and Edge Functions. Never in the frontend or the repo.
2. **Credit ledger is insert-only.** Never update or delete `credit_ledger` rows. Balance = sum of rows. Only the service role writes to it.
3. **Every agent run:** estimate → reserve (hold) → run with `maxBudgetUsd` = min(task cap, balance converted to USD) → settle actual cost → release the remainder. Failed runs caused by the platform are auto-refunded.
4. **Agents propose, the executor acts.** Anything external or irreversible (publish, send, spend, file) is written as a pending `approvals` row by the agent. A deterministic executor performs it only after approval. Agents never call external write APIs directly for these actions.
5. **Credits conversion:** credits = cost_usd × fx_gbp × markup ÷ credit_value (default: fx 0.75, markup 3, 1 credit = £0.01). Keep these values in config, not hard-coded.
6. **Models:** default Haiku for routine work (triage, drafts, summaries); Sonnet for planning and building. Model IDs in config.
7. **Claims and compliance:** public-facing text must pass the claims checker before it can be approved. UK rules: CAP Code, PECR for email marketing, UK GDPR.
8. **UK English, £, dates as 21 Oct 2026.**

## Conventions
- TypeScript strict. No `any` without a comment explaining why.
- Database access in the frontend via the generated Supabase types.
- All agent calls from the frontend go through `src/lib/agentClient.ts` (currently mocked; Phase 4 makes it real). Don't call agent endpoints from components directly.
- Skills live in `agent-service/skills/<name>/SKILL.md`. Company memory is generated per company from the database into the agent's workspace at run time.
- Tests: Vitest for frontend logic, plus SQL/RLS tests for permissions and the ledger. Add tests for anything touching money or permissions.

## Commands
Check `package.json` for the actual scripts; typical:
- `npm run dev`: frontend
- `supabase start` / `supabase db reset`: local database with seed
- `supabase gen types typescript --local > src/integrations/supabase/types.ts`
- `cd agent-service && npm run dev`: agent worker
